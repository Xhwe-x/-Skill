# 用户固定格式

## 来源和优先顺序

默认采用用户认可的技术服务文本格式；当前招标强制格式与用户新指示优先。

优先顺序：当前招标强制格式及暗标 → 用户新指示 → 本格式。只覆盖冲突参数，不随意改动整体风格。

## 使用模板

`assets/hospital-style.json` 保存参数；`assets/technical-bid-template.docx` 只保存干净样式和页脚，不包含医院、人员、旧图或历史正文。构建示例：

```python
from bid_format import new_document, add_heading, add_body, add_table, set_orientation
doc = new_document()
add_heading(doc, '项目理解', 1)
add_heading(doc, '需求分析', 2)
add_body(doc, '根据当前招标文件编写具体内容。')
add_table(doc, ['事项','责任','成果'], [['现状核验','项目负责人','基线清单']], [25,35,85])
doc.save('技术部分.docx')
```

表格总宽不能超过当节版心，宽表横向分节，禁止整篇改横向。单元格取消正文首行缩进。标题按内容需要使用，不为追求层数机械细分。

干净模板关闭文字对齐文档网格，以落实明确的1.5倍行距，避免源文网格叠加放大行距；这是对混排的统一处理。保存宋体和黑体的字体名称。渲染环境缺少原字体时记录替代条件，不能保证不同软件同页；最终页数要实测。

## 正文结构

默认从第一章正文开始，不加封面、说明、目录、评分索引或附件；招标文件强制要求或用户明确要求时例外。二级及以下标题均采用数字多级编号，随上级重启，导航窗格与正文的层级和编号一致；仅按内容需要增加级数。图表置于相关章节并提供实际内容。
